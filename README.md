# ejg2.com — static mirror for GitHub Pages

A fully static copy of [www.ejg2.com](https://www.ejg2.com) (originally a Squarespace
site), generated by [`tools/mirror.ts`](tools/mirror.ts) and ready to host on
GitHub Pages with the custom domain `www.ejg2.com`.

## What's here

```
index.html                  homepage (cover page)
<page>/index.html           every page from the sitemap + discovered links (29 pages)
assets/<host>/...           all Squarespace CDN assets, localized (css/js/images/fonts)
CNAME                       GitHub Pages custom domain: www.ejg2.com
.nojekyll                   skip Jekyll processing
404.html                    the site's 404 page
robots.txt, sitemap.xml     copied from the live site
tools/mirror.ts             Deno crawler that (re)generates the whole site
tools/check.ts              verifies every local reference resolves to a file
```

## Regenerating

Requires [Deno](https://deno.com) (no Node):

```sh
deno run --allow-net --allow-read --allow-write tools/mirror.ts   # re-crawl + rebuild
deno run --allow-read tools/check.ts                              # verify references
```

## Deploying (GitHub Pages)

1. Push this repo to GitHub (branch `main`).
2. Repo **Settings → Pages** → Source: **Deploy from a branch** → `main` → `/ (root)`.
3. **Settings → Pages → Custom domain**: enter `www.ejg2.com` (matches the `CNAME`
   file) and save. Wait for the DNS check to pass.
4. Once the certificate provisions, tick **Enforce HTTPS**.
5. (Recommended) **Settings → Pages → verify the domain** — see the TXT record below.
   Verification unlocks HTTPS enforcement for the apex domain too.

## DNS records

Point the domain away from Squarespace (delete the current `www →
ext-cust.squarespace.com` CNAME and the Squarespace apex A records) and add:

| Type  | Name | Value                    |
| ----- | ---- | ------------------------ |
| CNAME | www  | `<username>.github.io.`  |
| A     | @    | 185.199.108.153          |
| A     | @    | 185.199.109.153          |
| A     | @    | 185.199.110.153          |
| A     | @    | 185.199.111.153          |
| AAAA  | @    | 2606:50c0:8000::153      |
| AAAA  | @    | 2606:50c0:8001::153      |
| AAAA  | @    | 2606:50c0:8002::153      |
| AAAA  | @    | 2606:50c0:8003::153      |

Optional domain-verification record (value is shown in **Settings → Pages** when you
add and verify the domain):

| Type | Name                              | Value                      |
| ---- | --------------------------------- | -------------------------- |
| TXT  | `_github-pages-challenge-<username>.ejg2.com` | `<verification code>` |

Notes:

- The `CNAME` file pins the canonical host to `www.ejg2.com`. Once the apex A/AAAA
  records point at GitHub, `ejg2.com` 301-redirects to `www.ejg2.com` — the same
  behavior the Squarespace site has today.
- DNS can take minutes to hours to propagate; the Pages custom-domain check will
  keep retrying.

## Local preview

```sh
python3 -m http.server 8000   # then open http://localhost:8000/
```

## Known limitations

- **Contact form**: the homepage form renders, but submission needs Squarespace's
  backend, so it can't work on static hosting. The form's configured destination is
  `e@ejg2.com` — swap the button for a `mailto:` link or wire up a static form
  service (e.g. Formspree) if submissions are needed.
- **Fonts**: Adobe Fonts (Typekit) stays hotlinked to `use.typekit.net` — its kit
  expands font URLs from URI templates at runtime, and Adobe's licensing requires
  serving from their CDN. Works on `www.ejg2.com`; the `*.github.io` preview may
  fall back to system fonts.
- **Dynamic bits**: blog/project listing pagination, tag/author filters, search,
  and the contact-form POST are Squarespace backend features and are inert here.
  Every post listed in the sitemap is mirrored and directly reachable.
- A handful of directory-style URLs in Squarespace's inline config/JSON-LD still
  point at the CDN; they 404 on the live site too.
- JSON-escaped CDN URLs inside inline Squarespace config were deliberately left
  untouched (rewriting them risks breaking Squarespace's runtime JS; the CDN URLs
  keep working).
